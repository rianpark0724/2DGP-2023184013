# LEC10 소년 이동 및 입력 처리 개발 계획

## 1. 목적과 필수 요구사항

`PRE-PRD.md`를 기준으로 키보드 방향키로 소년을 이동시키고, 이동 여부와 바라보는 방향에 따라 애니메이션을 전환하는 프로그램을 개발한다.

- 작업 폴더: `2DGP-2023184013/Labs/LEC10_HandlingInputs`
- 개발 브랜치: `labs/lec10_handlinginputs`
- 실행 파일: `TUKwalking.py` 단일 Python 파일
- 라이브러리: pico2d 및 Python 표준 라이브러리
- 창 크기: 800 × 600
- 자원: 같은 폴더의 `animation_sheet.png`, `TUK_GROUND.png`
- 필수 기능: 상하좌우 이동, 좌우 방향 전환, 방향별 idle 애니메이션, 화면 경계 제한, Escape 및 창 닫기로 종료
- 개발 이력: 실제 기능을 점진적으로 구현하는 의미 있는 커밋 최소 12회

이 문서는 개발 계획이다. 코드 구현, 실행 검증 및 커밋이 완료되었다는 의미는 아니다. 아래의 속도, 초기 위치, 동시 입력 정책은 원문에 없는 사항을 구체화한 기본 설계값이다.

## 2. 범위와 산출물

실행에 필요한 코드와 상태, 설정 상수, 함수는 모두 `TUKwalking.py`에 작성한다. 기존 실습 파일과 원본 자산, `PRE-PRD.md`는 보존한다. 마우스 조작, 점프, 충돌 지형, 카메라 이동, 사운드, 추가 UI는 이번 구현 범위에 포함하지 않는다.

최종 산출물은 실행 코드와 이 문서에 기록한 검증 결과다. 기존 `character_runs_esc.py`의 이벤트 루프와 프레임 자르기 방식을 참고하되, 키 입력을 숫자로 누적하는 방식은 눌린 키 집합으로 개선한다.

## 3. 화면 및 자원 설계

배경은 창 중앙 `(400, 300)`에 800 × 600 크기로 그린다. 원본 배경 비율이 창과 다르면 창 크기에 맞추는 것을 기본으로 하며, 실제 출력에서 배경 구도를 확인한다. 캐릭터 초기 위치는 중심 `(400, 300)`, 초기 방향은 오른쪽이다.

자원 경로는 현재 작업 디렉터리가 아닌 `TUKwalking.py`의 위치를 기준으로 계산한다. 이미지는 시작 시 한 번만 로드하고, 실패하면 실패한 경로를 안내한 뒤 생성된 창을 정리한다.

제공된 스프라이트는 가로 8칸, 세로 4줄이며 기존 실습 코드의 프레임 크기는 100 × 100이다. 이미지를 확인한 결과와 pico2d의 좌하단 기준 좌표를 바탕으로 다음 매핑을 사용한다. 원본 이미지의 실제 크기와 잘라내기 결과는 구현 초기에 확인한다.

| 상태 | 이미지에서의 줄 위치 | 자르기 y 좌표 | 프레임 수 |
| --- | --- | --- | --- |
| 오른쪽 idle | 위에서 첫째 줄 | 300 | 8 |
| 왼쪽 idle | 위에서 둘째 줄 | 200 | 8 |
| 오른쪽 이동 | 위에서 셋째 줄 | 100 | 8 |
| 왼쪽 이동 | 위에서 넷째 줄 | 0 | 8 |

프레임 `i`의 영역은 `(i * 100, 행 y, 100, 100)`이다. 기본 출력 크기도 100 × 100으로 한다. idle에서도 8프레임을 반복 재생하며, 회색으로 보이는 시트 배경이 실제 출력에 남는지는 런타임에서 확인한다.

## 4. 입력과 이동 규칙

| 상황 | 처리 규칙 |
| --- | --- |
| 방향키 누름 | 해당 키를 눌린 키 집합에 추가 |
| 방향키 뗌 | 해당 키를 집합에서 제거; 중복 해제에도 오류가 없어야 함 |
| 키 자동 반복 | 집합으로 처리하여 이동 속도와 입력 상태가 누적되지 않음 |
| 좌우 또는 상하 동시 입력 | 해당 축의 이동량을 0으로 상쇄 |
| 서로 다른 축 동시 입력 | 대각선 이동 허용, 벡터 정규화로 직선과 동일한 속도 유지 |
| 왼쪽 또는 오른쪽 이동 입력 | 최종 수평 입력이 음수면 왼쪽, 양수면 오른쪽을 바라봄 |
| 수평 입력 없이 상하 이동 | 마지막 좌우 방향 유지 |
| 모든 축 입력이 상쇄되거나 키를 모두 뗌 | 현재 바라보는 방향의 idle 재생 |
| Escape 또는 창 닫기 | 루프를 종료하고 창 정리 |

기본 이동 속도는 초당 400픽셀이다. 루프 횟수 대신 경과 시간 `dt`로 위치를 갱신한다. 장시간 중단 후 갑자기 크게 이동하지 않도록 갱신에 사용할 `dt`는 최대 0.1초로 제한한다.

이동 애니메이션 선택은 상쇄 후의 이동 입력 벡터가 0인지로 판단한다. 경계에서 바깥 방향키를 계속 누르는 동안에도 이동 애니메이션을 재생한다. 키를 떼면 idle로 돌아간다.

화면 경계는 캐릭터 중심이 아니라 출력 사각형 전체를 기준으로 제한한다. 100 × 100 출력일 때 `50 ≤ x ≤ 750`, `50 ≤ y ≤ 550`로 위치를 보정한다. 따라서 모든 프레임이 창 내부에 남는다.

## 5. 애니메이션과 실행 구조

상태는 `idle_left`, `idle_right`, `move_left`, `move_right` 네 가지다. 기본 재생 속도는 초당 10프레임으로 하고, 경과 시간을 누적하여 0.1초마다 프레임을 전환한다. 8번째 프레임 다음에는 첫 프레임으로 돌아간다.

상태가 바뀌면 프레임과 애니메이션 누적 시간을 0으로 초기화한다. 상태가 유지되는 동안은 매 루프마다 초기화하지 않는다. 이동 중 상하 키를 추가하거나 제거해도 상태가 같으면 재생은 이어진다.

단일 파일 안에서 설정 상수, 입력 처리, 이동 갱신, 애니메이션 갱신, 그리기, 실행 진입점을 함수로 구분한다. 실행 순서는 다음과 같다.

1. 800 × 600 창 생성 및 이미지 로드
2. 위치, 방향, 눌린 키, 프레임, 시간 초기화
3. 이벤트 처리 후 종료 요청 확인
4. 경과 시간 계산, 이동 벡터와 방향 결정, 위치 및 경계 갱신
5. 애니메이션 상태와 프레임 갱신
6. 화면 지우기, 배경과 캐릭터 순서로 그리기, 화면 갱신
7. 짧은 루프 대기로 불필요한 CPU 점유 줄이기
8. 종료 또는 오류 시 창 정리

`if __name__ == '__main__':` 진입점과 `try/finally`를 사용한다. 종료 요청 이후에는 다음 프레임을 그리지 않는다. 실행 중 창 포커스를 잃으면 눌린 키를 비우는 처리를 검토한다. 해당 이벤트를 설치된 pico2d가 지원하는지 확인한 뒤 적용하며, 지원 여부는 검증 결과에 기록한다.

## 6. 단계별 개발 및 커밋 계획

각 단계에서 실제 변경과 확인을 마친 뒤 커밋한다. 완성 코드를 한 번에 작성한 후 이력만 나누거나 빈 커밋을 만드는 방식은 사용하지 않는다. 아래 14개 단계는 최소 12회 요구를 충족하도록 구성했으며, 문서 작성 커밋에 의존하지 않고 구현 단계로 요구 횟수를 충족한다. "hw_4-커밋 메시지" 형식을 사용하여 한국어로 커밋한다.

| 단계 | 구현 및 커밋 단위 | 단계별 확인 |
| --- | --- | --- |
| 01 | 단일 실행 파일, 진입점, 800 × 600 창 및 정리 구조 추가 | 구문 검사, 빈 창 표시 |
| 02 | 창 닫기와 Escape 이벤트 처리 추가 | 두 방식으로 정상 종료 |
| 03 | 스크립트 기준 자원 경로와 로드 실패 처리 추가 | 다른 폴더에서 로드, 오류 시 창 정리 |
| 04 | 배경 출력 및 화면 갱신 루프 추가 | 배경이 창 전체에 표시됨 |
| 05 | 프레임 상수 및 캐릭터 초기 출력 추가 | 중앙에서 첫 프레임 정상 표시 |
| 06 | 방향별 idle 프레임과 시간 기반 재생 추가 | 좌우 idle의 프레임 영역 검토 |

| 14 | 큰 시간 간격 보정, 가능한 포커스 해제 처리 및 최종 실행 안내 추가 | 예외 상황 점검, 검증 결과와 커밋 수 기록 |

최종 검증에서 발견한 결함은 별도 수정 커밋으로 해결한다. 단계는 의존 관계를 유지하는 범위에서 조정할 수 있으며, 단계별 실제 변경이 있어야 커밋 횟수에 포함한다.

## 8. 실행 안내와 완료 판정

Python과 pico2d가 설치된 환경에서 실습 폴더로 이동하여 `python TUKwalking.py`로 실행한다. 실제 개발 시 사용한 Python 및 pico2d 버전, 확인 날짜, 수용 기준별 결과와 남은 문제를 이 문서에 기록한다.

필수 기능 구현, 수용 기준 검증, 의미 있는 커밋 최소 12회가 모두 충족되면 개발 완료로 판정한다.

## 9. 구현 및 검증 기록 (2026-10-06)

14개 개발 단계의 기능을 `TUKwalking.py`에 구현했다. 문서 작성 커밋을 제외하고 구현 커밋 14회를 남긴다. 기존 실습 코드와 이미지 원본은 변경하지 않았다.

- 환경: Windows, Python 3.13.15, pico2d 1.5.1
- 실제 자원 크기: `animation_sheet.png` 802 × 402, `TUK_GROUND.png` 1280 × 1024
- 시트의 가장자리 여백을 포함한 실제 자르기 결과에서 100 × 100 격자와 지정 행 좌표가 정상임을 확인했다.
- 실제 SDL 렌더러로 4개 상태의 32프레임을 출력하고 캡처를 검토했다. 캐릭터 잘림이나 이웃 프레임 혼입이 없으며, 시트 배경은 투명하게 출력된다.
- pico2d의 `get_events()`는 창 포커스 이벤트를 전달하지 않는다. 따라서 `SDL_GetKeyboardFocus()`를 루프에서 확인하여 포커스가 없으면 눌린 키를 비운다.

검증용 스크립트는 저장소 밖의 작업 폴더에서 실행했고 제출 코드에 포함하지 않았다. 실제 렌더링 검증은 화면에 노출하지 않는 SDL 창에서 수행했으며, 이벤트는 SDL 큐에 주입했다.

### 현재 환경의 실행 방법

기본 `python` 명령은 Windows 앱 별칭으로 연결되어 실행되지 않았고, 기존 `.lec09-venv`의 Python 실행 파일은 삭제된 런타임을 가리킨다. 검증에서는 설치된 Python 3.13과 기존 가상환경의 pico2d 패키지 경로를 사용했다. 실습 폴더에서 PowerShell로 다음과 같이 실행할 수 있다.

```powershell
$env:PYTHONPATH = (Resolve-Path '..\..\..\.lec09-venv\Lib\site-packages').Path
& 'C:\Users\rianp\AppData\Local\Programs\Python\Python313\python.exe' .\TUKwalking.py
```

일반적인 Python 환경에 pico2d가 설치되어 있다면 기존 안내대로 `python TUKwalking.py`를 사용한다. 방향키로 이동하며 Escape 또는 창 닫기 버튼으로 종료한다.
