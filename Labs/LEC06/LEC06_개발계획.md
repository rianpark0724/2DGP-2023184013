# LEC06 점진적 개발 실습 — 코드 구현 계획

## 1\. 목적과 범위

* 참조 범위: 강의의 실습 목표, 함수 분해, 이미지 출력, 원운동, 공통 그리기 함수, 사각 운동, 삼각 운동, 전체 통합 내용(주로 슬라이드 6–20).
* 제외 범위: Git, 커밋, push, 저장소 관리, 제출 절차.

이번 산출물: 개발 계획 Markdown 문서만 작성한다. Python 코드 구현 및 실행은 이후 단계에서 진행한다.2. 구현 목표와 기준값

각 도형의 시작점은 서로 다르다. 따라서 도형이 바뀔 때 다음 도형의 시작점으로 위치가 바뀌는 것은 허용한다. 강의에서 요구하지 않은 도형 사이의 연결 이동은 추가하지 않는다. 같은 도형 안에서는 각 변의 끝점과 다음 변의 시작점이 일치해야 한다.

## 3\. 코드 구성 계획

실습 규모에 맞춰 Python 파일 하나에 작성한다. 클래스나 여러 모듈로 확장하기보다 강의의 함수 분해 방식이 보이도록 구성한다. 파일명은 `lec06\_motion.py`를 사용할 계획이며, 이는 강의의 지정값이 아닌 본 계획의 선택이다.

파일 내부 순서는 다음과 같다.

1. `pico2d`와 `math` 가져오기.
2. 화면 크기, 원의 중심·반지름, 프레임 대기 시간 등 기준값 선언.
3. 공통 그리기 함수와 이동 함수 정의.
4. 캔버스 열기 및 캐릭터 이미지 로드.
5. 세 운동을 순서대로 호출하는 전체 반복문 실행.

강의 예제처럼 이미지 객체 `boy`는 초기화 후 각 함수에서 참조하도록 한다. 이미지를 프레임마다 다시 읽지 않는다. `boy`를 사용하는 함수는 이미지 로드가 끝난 뒤 호출한다.

### 함수별 책임

|함수|책임|완료 조건|
|-|-|-|
|`draw\_boy(x, y)`|지우기 → 캐릭터 그리기 → 화면 갱신 → 대기|한 프레임 출력 후 반환|
|`move\_circle()`|각도에 따른 원 좌표 계산 및 출력|0–359도 이동 후 반환|
|`move\_rectangle()`|상단 → 오른쪽 → 하단 → 왼쪽 함수 호출|네 변 실행 후 반환|
|`move\_top()`|사각형 상단을 오른쪽으로 이동|`(750, 550)` 도달|
|`move\_right()`|오른쪽 변을 아래로 이동|`(750, 50)` 도달|
|`move\_bottom()`|하단을 왼쪽으로 이동|`(50, 50)` 도달|
|`move\_left()`|왼쪽 변을 위로 이동|`(50, 550)` 도달|
|`move\_triangle()`|A→B, B→C, C→A 함수 호출|세 변 실행 후 반환|
|`move\_ab()`|삼각형 A에서 B로 이동|B 도달|
|`move\_bc()`|삼각형 B에서 C로 이동|C 도달|
|`move\_ca()`|삼각형 C에서 A로 이동|A 도달|

삼각형의 변 함수 이름은 본 계획에서 정한 것이다. 강의가 요구하는 세 변의 함수 분해를 유지하고, 각 함수 안에서 선형 보간을 계산한다. 별도의 범용 선분 함수는 초기 구현에 추가하지 않아 각 변의 계산과 진행 방향을 직접 비교할 수 있게 한다.

## 4\. 운동별 계산 방법

### 4.1 원운동

각도를 0도부터 359도까지 1도씩 증가시킨다. 매 단계에서 도를 라디안으로 바꾸고 다음 식으로 좌표를 구한다.

* `theta = math.radians(degree)`
* `x = 400 + 200 \* math.cos(theta)`
* `y = 300 + 200 \* math.sin(theta)`

계산한 좌표를 `draw\_boy(x, y)`로 전달한다. 오른쪽에서 출발하여 반시계 방향으로 이동한다.

|각도|예상 좌표|
|-|-|
|0도|`(600, 300)`|
|90도|`(400, 500)`|
|180도|`(200, 300)`|
|270도|`(400, 100)`|

강의의 `range(360)`을 유지하므로 360도는 별도로 그리지 않는다. 마지막 프레임은 359도이며 정확히 출발 좌표에서 끝나는 것은 아니다. 부동소수점 계산으로 기준 좌표에 미세한 오차가 생길 수 있다.

### 4.2 사각 운동

왼쪽 위에서 출발해 시계 방향으로 이동한다. 한 변에서는 한 좌표만 바꾸고 나머지는 고정한다. 좌표 변화량은 프레임당 5로 둔다.

|구간|시작 → 끝|좌표 생성 계획|
|-|-|-|
|상단|`(50, 550)` → `(750, 550)`|y=550, x는 `range(50, 751, 5)`|
|오른쪽|`(750, 550)` → `(750, 50)`|x=750, y는 `range(550, 49, -5)`|
|하단|`(750, 50)` → `(50, 50)`|y=50, x는 `range(750, 49, -5)`|
|왼쪽|`(50, 50)` → `(50, 550)`|x=50, y는 `range(50, 551, 5)`|

각 변은 시작점과 끝점을 모두 포함한다. 인접한 변에서 모서리가 두 번 그려지는 것은 허용하고, 초기 구현에서는 중복 제거를 하지 않는다. 감소 구간의 간격 부호와 `range()`의 끝값 제외 규칙을 특히 확인한다.

### 4.3 삼각 운동

A → B → C → A 순서로 이동한다. 시작점 `(x0, y0)`와 끝점 `(x1, y1)` 사이를 같은 진행 비율 `t`로 보간한다.

* `t = step / n`
* `x = x0 + (x1 - x0) \* t`
* `y = y0 + (y1 - y0) \* t`

각 변에서 `step`을 0부터 n까지 포함하여 시작점과 끝점이 모두 그려지게 한다. 강의는 양의 정수 n만 요구하므로, 본 계획에서는 우선 **모든 변에 n=100**을 사용한다.

|구간|x 변화|y 변화|t=0.5일 때 좌표|
|-|-|-|-|
|A→B|100 → 700|100 유지|`(400, 100)`|
|B→C|700 → 400|100 → 500|`(550, 300)`|
|C→A|400 → 100|500 → 100|`(250, 300)`|

각 변의 길이는 AB=600, BC=500, CA=500이므로 동일한 n과 대기 시간을 사용하면 AB에서 프레임당 이동 거리가 더 크다. 도형 전체의 일정한 이동 속도는 강의의 필수 요구사항이 아니므로 이번 기준 구현에는 추가하지 않는다. 추후 코드 비교 시 n의 선택과 속도 차이를 비교 항목으로 다룬다.

## 5\. 점진적 개발 순서

각 단계는 **작은 기능 작성 → 해당 부분 실행 → 예상 결과 확인 → 다음 단계 진행** 순서로 수행한다. 실패하면 다음 기능을 추가하기 전에 현재 변경을 수정한다.

|단계|작성 또는 수정할 내용|확인할 결과|
|-|-|-|
|1|최상위 무한 반복 구조 작성|실행 오류 없이 반복 구조가 유지됨; IDE에서 중단|
|2|세 운동 함수 정의 및 호출 순서 배치|함수 정의와 호출 관계가 준비됨|
|3|각 운동 함수에 임시 출력문 추가|`circle`, `rectangle`, `triangle` 순서; 임시 `break`로 한 묶음 확인|
|4|캔버스와 이미지 준비, 중앙에 1회 출력|`(400, 300)`에 표시하고 1초 뒤 닫힘|
|5|원운동 좌표 계산과 프레임 출력 구현|반시계 방향 이동, 기준 좌표 통과, 한 번 실행 후 반환|
|6|사각형 네 변 함수를 정의하고 출력문으로 연결|`top`, `right`, `bottom`, `left` 순서|
|7|반복되는 화면 처리 코드를 `draw\_boy()`로 추출|원운동의 위치·방향·출력 동작이 이전과 같음|
|8|사각형 상단 구현|y 고정, x 증가, 양 끝점 일치|
|9|오른쪽 변 구현|x 고정, y 감소, 상단 끝점에서 연결|
|10|하단 구현|y 고정, x 감소, 오른쪽 끝점에서 연결|
|11|왼쪽 변 구현 및 사각형 통합|x 고정, y 증가, 한 바퀴 후 출발점 복귀|
|12|삼각형 세 변 함수를 정의하고 호출 순서 확인|A→B → B→C → C→A 순서|
|13|A→B 보간 구현|수평 이동, B 도달|
|14|B→C 보간 구현|x 감소와 y 증가가 함께 일어나며 C 도달|
|15|C→A 보간 구현 및 삼각형 통합|A로 복귀하고 함수 반환|
|16|최상위 반복 복구 및 임시 검증 코드 정리|원 → 사각 → 삼각 순서를 두 차례 이상 반복|

부분 검증에서는 캔버스와 이미지 초기화를 유지하고, 전체 반복문 자리를 현재 확인할 함수 호출로 잠시 대체한다. 무한 반복문 아래에 테스트 호출을 추가하지 않는다. 전체 통합 전에 단독 테스트 호출, 임시 `break`, 불필요한 출력문을 정리한다.

## 6\. 검증 기준과 주의점

### 실행 환경 및 화면

* `pico2d`를 사용할 수 있는 실행 환경을 준비한다.
* `character.png`가 실행 작업 폴더를 기준으로 로드되는지 확인한다.
* 캔버스와 이미지는 이동 전에 준비하며, 이동 중에 다시 생성하지 않는다.
* 매 프레임 지우기 → 그리기 → 갱신 → 대기 순서를 지킨다.
* 이미지 중심의 경로와 이미지 전체가 화면 안에 보이는지는 구분한다. 사각 경로의 여백이 50이므로 이미지 크기에 따라 가장자리가 잘릴 수 있다. 실제 이미지 크기를 확인하고, 표시 크기를 바꿀 필요가 있다면 비교 조건에 기록한다.

### 경로 및 제어 흐름

* 원운동의 중심, 반지름, 회전 방향이 기준값과 일치한다.
* 사각형은 네 모서리에 도달하고, 같은 도형 안에서 위치가 튀지 않는다.
* 삼각형은 각 변의 시작점·중간점·끝점이 보간식과 일치한다.
* 각 운동 함수 내부에는 끝나지 않는 반복을 두지 않는다.
* 삼각 운동 종료 후 다시 원운동이 시작되는 것을 포함해 전체 순환을 두 번 이상 관찰한다.
* 도형 사이의 시작점 전환은 허용하지만, 도형 내부의 경로 단절은 오류로 본다.

### 종료 방식

강의의 기본 구조에는 종료 입력 처리가 없다. 이번 기준 구현도 확인을 마치면 IDE에서 중단하는 방식으로 계획한다. 단독 검증처럼 유한 실행에서는 마지막에 캔버스를 닫되, 무한 반복문 뒤의 `close\_canvas()`가 정상 실행 중 자동으로 호출될 것으로 가정하지 않는다. 키보드 종료 기능이나 별도 이벤트 루프는 이번 계획의 필수 구현에 포함하지 않는다.

## 7. 구현 완료 판단 체크리스트

아래 항목은 이후 코드 작성 단계에서 확인한다. 현재 체크되지 않은 상태가 계획 문서의 정상 상태다.

* \[ ] 캐릭터 이미지가 정상적으로 표시된다.
* \[ ] 원운동이 지정한 중심과 반지름으로 한 바퀴 실행된다.
* \[ ] 사각 운동의 네 변이 지정된 방향과 좌표로 연결된다.
* \[ ] 삼각 운동의 세 변이 연결되고 A로 돌아온다.
* \[ ] 공통 그리기 함수가 모든 운동에서 사용된다.
* \[ ] 각 운동이 끝난 후 다음 운동으로 넘어간다.
* \[ ] 전체 순서가 두 차례 이상 반복된다.
* \[ ] 부분 검증용 코드가 최종 실행을 방해하지 않는다.
* \[ ] 본 계획에서 변경한 설계가 있다면 실제 코드와 비교할 수 있도록 기록한다.
