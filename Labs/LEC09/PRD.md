# LEC09 애니메이션 뷰어 개발 요구사항 명세서

## 1. 문서 목적과 기준

`PRE-PRD.md`를 기준으로 `sonic-sprite.png`의 모든 애니메이션을 순차 재생하는 뷰어를 구현한다. 이 문서는 구현 범위, 재생 규칙, 개발 단계와 완료 판정 기준을 정의한다.

- 작업 위치: `2DGP-2023184013/Labs/LEC09`
- 개발 브랜치: `feature/lec09-animation-viewer`
- 구현 언어 및 그래픽 라이브러리: Python, pico2d
- 실행 진입점: `animation_viewer.py`
- 이미지 자산: 같은 폴더의 `sonic-sprite.png`
- 개발 방식: 기능을 단계적으로 구현하고 최소 20회의 의미 있는 커밋을 남긴다.

초안에서 지정한 항목은 필수 요구사항이다. 아래의 창 크기, 재생 속도, 배율, 대기 화면과 종료 키는 구현을 구체화하기 위한 기본 설계값이며, 실제 시인성 검증에 따라 조정할 수 있다. 조정해도 5회 반복, 1초 대기, 전체 무한 순환 규칙은 유지한다.

## 2. 목표와 범위

### 2.1 사용자 목표

사용자는 프로그램을 실행하는 것만으로 스프라이트 시트의 모든 동작을 확대된 크기로 확인할 수 있어야 한다. 각 동작은 5회 반복되며, 동작 사이에는 1초의 정지 구간이 있어야 한다.

### 2.2 포함 범위

- 스프라이트 시트 분석과 동작별 프레임 목록 작성
- 프레임 영역을 잘라 화면 중앙에 확대 출력
- 시간 기반 프레임 전환
- 동작별 5회 반복과 동작 사이 1초 대기
- 마지막 동작 이후 첫 동작으로 돌아가는 무한 재생
- 창 닫기 및 Escape 키를 통한 정상 종료
- 이미지 로드 실패 시 원인을 알 수 있는 오류 안내

### 2.3 제외 범위

수동 동작 선택, 재생 속도 조절 UI, 일시정지 버튼, 이미지 편집, 외부 시트 가져오기, 사운드, 게임 조작, 실행 파일 패키징은 이번 구현에 포함하지 않는다. 필요하면 필수 기능 완료 후 별도 요구사항으로 다룬다.

## 4. 스프라이트 분석 요구사항

### 4.1 확인된 이미지 특성

현재 제공된 이미지에는 여러 줄에 걸친 캐릭터 프레임과 상단 제목, 하단 제작자 표기 및 부가 이미지가 함께 존재한다. 프레임의 크기와 간격이 일정한 격자라고 가정하지 않는다. 한 줄 전체가 반드시 한 동작이라고 단정하지 않는다.

### 4.2 분석 및 목록화

구현 초기에 이미지를 확대하여 다음 항목을 확정하고 `animation_viewer.py`의 데이터와 주석에 기록한다.

| 항목        | 기록 내용                                                  |
| ----------- | ---------------------------------------------------------- |
| 동작 ID     | 중복되지 않는 내부 식별자                                  |
| 동작 이름   | 이미지에서 식별 가능한 이름, 불확실하면 중립적인 임시 이름 |
| 재생 순서   | 전체 동작 순환에서의 순서                                  |
| 프레임 목록 | 각 프레임의 잘라내기 좌표와 너비·높이                     |
| 프레임 순서 | 동작 내 표시 순서                                          |
| 정렬 기준   | 프레임별 기준점 또는 보정값                                |
| 분류 근거   | 동작 경계와 부가 이미지의 포함·제외 이유                  |

연속된 움직임을 구성하는 모든 동작을 포함한다. 제목과 제작자 문구는 프레임에서 제외한다. 하단 부가 이미지나 단일 포즈는 실제 동작 구성 여부를 확인해 포함·제외 근거를 남긴다. 애니메이션에 속하는 단일 프레임 동작은 1프레임 애니메이션으로 처리할 수 있다.

정확한 동작 수와 프레임 수는 아직 확정하지 않는다. 분석 결과로 확정한 목록을 전체 재생의 검증 기준으로 사용하며, 분류가 모호한 영역은 기록 없이 누락하지 않는다. 기본 탐색 순서는 위에서 아래, 같은 줄에서는 왼쪽에서 오른쪽으로 하되 실제 동작의 연속성에 맞춰 그룹을 구성한다.

### 4.3 좌표와 자르기

- 원본 좌표를 좌상단 기준으로 기록할 경우, pico2d의 이미지 자르기에 사용할 좌표로 변환하는 처리를 한곳에 둔다.
- 이미지 높이가 `H`이고 좌상단 기준 영역이 `(x, y, w, h)`라면 좌하단 기준 영역은 `(x, H - y - h, w, h)`로 계산한다.
- 모든 영역은 이미지 경계 안에 있어야 하며, 너비와 높이는 양수여야 한다.
- 캐릭터 일부가 잘리거나 이웃 프레임과 문자가 함께 표시되지 않아야 한다.
- 프레임 크기가 달라도 동일한 기준점으로 정렬해 불필요한 화면 흔들림을 줄인다. 기본은 하단 중앙 기준이며, 공중 동작 등은 의도된 이동을 보존하도록 보정한다.

## 5. 기능 요구사항

| ID    | 요구사항                                              | 완료 기준                                                              |
| ----- | ----------------------------------------------------- | ---------------------------------------------------------------------- |
| FR-01 | 프로그램 시작 시 창을 열고 이미지를 한 번 로드한다.   | 실행 후 첫 동작의 첫 프레임이 표시된다.                                |
| FR-02 | 목록에 정의된 모든 동작을 순서대로 재생한다.          | 누락·중복 없이 목록 순서와 화면 순서가 일치한다.                      |
| FR-03 | 각 동작을 정확히 5회 반복한다.                        | 첫 프레임부터 마지막 프레임까지의 표시가 5회 완료된다.                 |
| FR-04 | 5회 완료 후 1초간 대기한다.                           | 마지막 프레임을 유지하고 대기 종료 전에는 다음 동작을 표시하지 않는다. |
| FR-05 | 대기 종료 후 다음 동작으로 전환한다.                  | 다음 동작의 첫 프레임과 첫 반복부터 시작한다.                          |
| FR-06 | 마지막 동작 뒤에도 1초 대기하고 첫 동작으로 돌아간다. | 최소 두 번의 전체 순환 동안 자동 재생이 유지된다.                      |
| FR-07 | 프레임을 확대한다.                                    | 원본보다 크게 보이고 종횡비가 유지되며 화면 경계에서 잘리지 않는다.    |
| FR-08 | 재생 및 대기 중 종료 입력을 처리한다.                 | 창 닫기 또는 Escape 입력 시 정상 종료한다.                             |
| FR-09 | 실행 위치와 무관하게 이미지 경로를 찾는다.            | 이미지 경로를 스크립트 파일 위치 기준으로 해석한다.                    |
| FR-10 | 이미지 로드 실패를 안내한다.                          | 실패한 경로를 포함한 메시지를 남기고 창 자원을 정리한다.               |

## 6. 재생 규칙과 상태 설계

### 6.1 기본 설정

| 설정              | 기본값                    | 비고                                                  |
| ----------------- | ------------------------- | ----------------------------------------------------- |
| 창 크기           | 800 × 600                | 모든 확대 프레임이 여유 있게 표시되는지 확인          |
| 프레임 재생 속도  | 초당 10프레임             | 기본 프레임 표시 시간 0.1초                           |
| 확대 배율         | 4배                       | 가로·세로에 동일한 배율 적용, 자산 분석 후 조정 가능 |
| 동작 반복 횟수    | 5회                       | 초안의 필수값                                         |
| 동작 간 대기 시간 | 1.0초                     | 초안의 필수값                                         |
| 대기 화면         | 현재 동작의 마지막 프레임 | 대기 중 프레임 진행 정지                              |

프레임이 `N`개이고 재생 속도가 `F` FPS인 동작의 1회 재생 시간은 `N / F`초이며, 5회 재생 후 다음 동작까지의 명목 시간은 `5 × N / F + 1`초다. 마지막 프레임도 다른 프레임과 같은 표시 시간을 채운 뒤 반복 완료를 계산한다.

### 6.2 상태와 데이터

동작 목록, 현재 동작 인덱스, 현재 프레임 인덱스, 완료한 반복 횟수, 프레임 누적 시간, 대기 경과 시간, 실행 여부를 관리한다. 재생 상태는 `PLAYING`과 `WAITING`으로 구분한다.

1. 시작 시 첫 동작, 첫 프레임, 완료 반복 0회, `PLAYING`으로 초기화한다.
2. 프레임 표시 시간이 지나면 다음 프레임으로 이동한다.
3. 마지막 프레임의 표시 시간이 끝나면 완료 반복 횟수를 1 증가시킨다.
4. 완료 반복이 5회 미만이면 같은 동작의 첫 프레임으로 돌아간다.
5. 5회가 되면 마지막 프레임을 유지하고 `WAITING`으로 전환한다.
6. 대기 1초가 끝나면 다음 동작으로 이동하고 반복·프레임·시간 상태를 초기화한다.
7. 다음 동작이 목록 끝을 넘으면 첫 동작으로 돌아간다.

### 6.3 시간과 이벤트 처리

- 프레임 진행은 루프 횟수가 아닌 단조 증가 시간의 경과량을 기준으로 한다.
- 매 루프에서 이벤트 처리, 상태 갱신, 그리기 순서를 유지한다.
- 1초 대기를 긴 블로킹 sleep으로 구현하지 않는다. 대기 중에도 창 닫기와 Escape를 처리한다.
- 일반적인 작은 처리 지연은 누적 시간을 보존해 재생 속도 오차를 줄인다.
- 창 이동이나 디버깅으로 긴 지연이 생기면 한 번에 여러 동작을 건너뛰지 않도록 보정한다. 이 경우 실제 재생이 길어지는 것은 허용하되 동작과 반복 횟수를 생략하지 않는다.
- 대기 시간은 대기 상태 진입 후 실제 경과 시간으로 측정하고, 이전 프레임의 잔여 시간 때문에 대기가 짧아지지 않게 한다.

## 7. 코드 구성과 화면 품질

단일 파일 안에서 설정 상수, 동작 데이터, 좌표 변환, 상태 갱신, 프레임 출력, 실행 루프를 함수와 데이터로 구분한다. 이미지 로드와 창 생성은 프레임 루프 밖에서 수행한다. 실행 진입점은 `if __name__ == '__main__':` 구문으로 보호한다.

화면에는 현재 동작 하나만 표시한다. 배경은 캐릭터를 식별하기 쉬운 단색을 사용한다. 불필요한 잔상이 남지 않도록 매번 화면을 지우고 새 프레임을 그린다. 원본의 투명도와 배경 처리는 실제 로드 결과를 확인한 뒤 결정한다. 외부 폰트 등 추가 자산에 의존하는 UI는 필수로 두지 않는다.

## 8. 단계별 개발 및 커밋 계획

완성 코드를 한 번에 작성한 뒤 커밋만 나누지 않는다. 각 단계에서 구현 또는 분석 결과를 만들고, 해당 결과를 확인한 후 커밋한다. 아래 22개 단계는 최소 20회 요구를 충족하기 위한 계획이며, 빈 커밋과 의미 없는 수정은 횟수에 포함하지 않는다. 본 문서 작성 시점에는 아래 구현과 커밋이 완료된 것으로 간주하지 않는다. 커밋 메시지는 "hw_3-커밋 메시지" 양식에 맞춰 한글로 커밋 한다.

## 10. 구현 전 확정 및 완료 조건

구현 초기에 동작별 프레임 목록, 부가 이미지 분류, 정렬 보정값을 확정한다. 실행 환경의 Python 및 pico2d 버전은 실제 구동 확인 후 기록한다. 이미지 분석만으로 판별할 수 없는 동작 경계는 불확실한 항목으로 명시하고 재생 결과를 통해 검토한다.

FR-01부터 FR-10까지 구현되고 AC-01부터 AC-13까지 검증되며, 단계별 개발 커밋이 최소 20회 존재할 때 완료로 판정한다. 최종 실행 명령은 LEC09 폴더에서 `python animation_viewer.py`이며, 실행 안내에는 필요한 pico2d 설치 환경과 확인된 제약을 함께 기록한다.
