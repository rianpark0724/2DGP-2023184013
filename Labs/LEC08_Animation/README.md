# Drill #8 — 레이무 애니메이션 뷰어

Python과 pico2d로 만든 스프라이트 애니메이션 뷰어다. 서로 다른 4개 동작을 화면 중앙에서 확대 재생하며, 각 동작을 5회 재생한 뒤 마지막 프레임을 1초 유지하고 다음 동작으로 넘어간다. 마지막 동작 이후에는 첫 동작부터 다시 반복한다.

## 실행에 필요한 파일

| 경로 | 역할 |
| --- | --- |
| `LEC08/animation_viewer.py` | 실행 파일 |
| `LEC08/assets/reimu_sheet.png` | 2976×6777 크기의 원본 스프라이트 시트 |
| `LEC08/assets/animations.json` | 동작별 프레임 영역, 기준점, 재생 속도 |
| `LEC08/README.md` | 실행 방법과 구현 설명 |
| `LEC08/assets/ui.ttf` | 선택 사항: 화면 안내용 글꼴 |

이미지와 JSON은 실행 파일의 위치를 기준으로 찾는다. 따라서 저장소 루트와 LEC08 폴더 중 어느 위치에서 실행해도 같은 자료를 사용한다.

## 실행 방법

Python과 pico2d가 설치된 수업용 환경에서 실행한다. 이미 정상 작동한 환경을 그대로 사용한다.

저장소 루트에서 실행:

```bash
python LEC08_Animation/animation_viewer.py
```

LEC08 폴더 안에서 실행:

```bash

```

## 동작과 조작 방법

| 키 | 동작 ID | 동작 | 프레임 수 | 재생 속도 |
| --- | --- | --- | ---: | ---: |
| `1` | `idle` | 대기 · 지팡이 회전 | 18 | 8 FPS |
| `2` | `move` | 이동 · 전진 비행 | 12 | 12 FPS |
| `3` | `attack` | 일반 공격 · 지팡이 찌르기 | 10 | 12 FPS |
| `4` | `special` | 특수 공격 · 회전 베기 | 15 | 10 FPS |
| `Escape` 또는 창 닫기 | — | 프로그램 종료 | — | — |

별도의 입력 없이 대기 → 이동 → 일반 공격 → 특수 공격 순서로 자동 순환한다. 숫자 키를 누르면 해당 동작의 첫 프레임과 완료 횟수 0부터 다시 시작하며, 이후에는 그 동작 다음 순서로 자동 순환한다. 대기 중에도 같은 조작이 가능하다.

화면 하단에는 현재 동작, 재생/대기 상태, 완료 횟수, 프레임 번호, FPS, 남은 대기 시간을 표시한다. `Completed`는 현재 몇 번째 반복을 재생 중인지가 아니라 **끝까지 재생한 횟수**다.

글꼴은 `assets/ui.ttf`를 먼저 찾고, 없으면 코드에 등록한 시스템 글꼴 경로를 확인한다. 사용할 수 있는 글꼴이 없으면 애니메이션을 계속 재생하면서 콘솔로 상태를 안내한다. 화면 안내에는 영문 동작 ID를 사용한다.

## 기본 요구사항 구현

- **4종의 애니메이션:** 서로 다른 동작 4종, 총 55개의 프레임을 등록했다.
- **화면 중앙 표시:** 프레임별 기준점이 800×600 창의 중앙에 오도록 그리기 위치를 보정한다.
- **비율 유지 확대:** 대기의 첫 프레임 높이 166픽셀을 창 높이의 55%인 330픽셀에 맞춘다. 약 1.988배의 공통 배율을 모든 프레임에 적용한다.
- **정확한 반복 횟수:** 실제 경과 시간과 동작별 FPS로 진행된 프레임 수를 계산한다. 마지막 프레임의 표시 시간이 끝날 때 완주 횟수가 증가한다.
- **5회 재생 후 1초 대기:** 5회 완주 시 마지막 프레임을 유지하는 대기 상태로 전환한다. 이벤트 처리를 계속하면서 1초 경과 여부를 확인한다.
- **전체 무한 반복:** 대기 종료 후 다음 동작으로 이동하고, 마지막 동작 다음에는 첫 동작으로 돌아간다.

재생 시간은 화면 갱신 횟수가 아니라 `perf_counter()`로 얻은 경과 시간을 기준으로 계산한다. 화면 갱신이 지연되면 중간 프레임을 건너뛰어 현재 시간에 해당하는 프레임을 표시할 수 있다. 대기 시간은 대기 상태에 진입한 시점부터 계산한다.

## 선택 과제 1 — 프레임마다 크기가 다른 복잡한 시트 지원

균등한 격자로 시트를 나누지 않고, 각 프레임에 `left`, `top`, `width`, `height`를 따로 기록했다.

| 예시 프레임 | 원본 폭 | 원본 높이 |
| --- | ---: | ---: |
| `idle_01` | 110 | 166 |
| `idle_02` | 117 | 168 |
| `attack_01` | 143 | 159 |
| `attack_02` | 146 | 128 |

`draw_frame()`은 현재 프레임의 실제 폭과 높이로 원본 영역을 잘라내고, 각 치수에 공통 배율을 곱해 표시한다. 크기가 다른 프레임을 동일한 출력 사각형에 맞추지 않으므로 캐릭터 비율을 유지한다.

`anchor_x`, `anchor_y`는 잘라낸 프레임의 좌상단을 기준으로 한 정렬 기준점이다. `get_draw_position()`에서 기준점과 사각형 중심의 차이를 보정한다. 기준점이 생략되면 프레임 중심을 사용한다.

JSON 좌표는 좌상단 기준이며, pico2d로 잘라낼 때 아래쪽 좌표를 **이미지 높이 − top − height**로 변환한다. 원본 영역에는 무기와 공격 이펙트도 포함한다.

## 선택 과제 2 — 애니메이션마다 다른 프레임 수 지원

동작별 프레임 수는 각각 **18, 12, 10, 15개**다. 공통 프레임 수를 사용하지 않고, 선택한 동작의 프레임 목록 길이로 프레임 인덱스와 완주 횟수를 계산한다.

각 동작은 JSON에 별도의 `fps`를 갖는다. 동작이 바뀌면 프레임 목록, FPS, 시작 시간, 완료 횟수, 프레임 인덱스, 재생/대기 상태를 함께 초기화한다. `fps`를 생략하면 기본값 10을 사용한다.

## 데이터 오류 처리

실행 전 다음 항목을 검사한다.

- JSON 문법과 최상위 구조
- 비어 있는 동작 목록 또는 프레임 목록
- 음수 좌표, 0 이하의 크기, 정수가 아닌 영역 값
- 프레임 내부 범위를 벗어난 기준점 또는 유한하지 않은 기준점
- 실제 이미지 경계를 벗어난 프레임 영역
- 0 이하이거나 유한하지 않은 재생 속도

프레임 관련 오류에는 해당 동작과 프레임 번호를 포함한다. 이미지 로딩 이후 오류가 발생해도 종료 정리에서 캔버스를 닫는다.
